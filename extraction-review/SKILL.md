# 抽取/迁移评审

**原样搬过去的代码按构造就是逐字忠实的;重新实现的——新的 reader、loader、parser、dispatcher——
只和比较它的那次评审一样忠实。**

> 用户的原话值得内化:**这个代码库非常复杂、耦合很重,改一行都可能引起回归。**
> 所以每次改动都偏向**最小爆炸半径**,而那通常意味着**删掉一条并行路径**,而不是往它上面加补偿。

## 什么时候用

1. 推任何**重新实现**了 legacy 组件的 PR 之前(读持久化数据的、按 legacy 常量分派的)。
2. **QE 交接前对整条分支扫一遍**——某个检查项存在之前就合并的代码,从来没被它查过。
   按次推送的习惯会**静默豁免掉最早、通常也最危险的那几层**。

## 一眼看完

- **抽取不改变任何行为。** 没有"顺手改好一点"。
- 对齐要覆盖**整条 legacy 调用链**,而且要**跑在 legacy 写出来的产物上**,不是 happy-path 解码。
- 逐行查等价性。**被删掉的 null 守卫、新加的 `?? default`,是两只金丝雀。**
- 合并时**取所有副本守卫的并集**。
- **见证者必须待在契约外面。**
- **值相等不等于身份相等。**
- 一列可以承载两种**有意为之**的语义。不要去"统一"两个读取方。
- **重新定型会静默合并来源。** 枚举旧对象各自是对着谁解析的。
- 死代码要**可达性地图**,不是引用清单。**兄弟类型读起来像子类型。**
- 零引用门要 grep **每一种访问写法**。**报增量,绝不报绝对的零。**
- **消除引用,不要重新分配它们。**
- 一个用例一条抽取路径;**因排期而生的缝,在共享路径落地的那次改动里就退役。**
- 改动按**用例端到端**切。符号的退役是**结果**,不是目标。

## 一、抽取不改变任何行为

> **永远。** 工作是把代码**抽取**进分层或新结构时,行为不变。语义、生命周期、线程模型、可变性规则、
> 谁调谁、可观察的副作用、错误处理、事件顺序:**全部原样保留**。唯一变的是每一块住在哪个程序集、
> 以及它叫什么。

**为什么**:抽取的全部前提就是宿主应用的测试、运行时行为和集成面**不变**——这才是一次结构重构能不做
回归排查就发出去的原因。任何"更安全"或"更好"的改动混进来,都会打破这个契约,**把一次低风险的结构移动
变成一次需要自己的测试计划和回滚方案的行为重设计。**

## 二、整条链对齐,跑在 legacy 写出来的产物上

"忠实"覆盖的是**从消费方到字节的整条 legacy 调用链**,不只是核心算法。

> **出事经过**:一次外部评审抓到两个 CRITICAL,分支评审和对齐夹具都漏了,来自同一个盲点——
> **夹具永远只读当前写入方刚刚产出的文件**,所以它**永远不可能**触发 legacy 的二进制回退、
> 过期版本门、或者更老的索引方式。

**怎么用**:

1. **追完整条链**:入口守卫、存在性检查、版本与有效性门、格式回退、锁、把异常降级成"没有数据"。
   **每一个都是行为,不是管道。** 每一个都移植过去,或者有意识地记录下来。
2. **对齐矩阵必须包含旧版本写出来的产物**:旧二进制格式、过期版本戳、被截断的布局、缺失的伴生文件。
   **没有夹具就在测试里手工造出 legacy 的字节布局。**
3. **哨兵值和魔数必须来自 legacy 当初查询的那个 provider 或 dispatch**,复现它按类型、按路由的分派,
   **绝不从存储形状或类型形状里重新推导**。
4. 改哨兵值时,**扫一遍所有按旧值校准过的消费方**。基于形状的守卫会静默变错。
5. **给一个消费方改路由时,跑那个消费方项目自己的测试套件**,不只是被抽取那个上下文的。
   **消费方已有的测试是对"改路由之前的契约"的一份免费刻画**,而**一次它们的桩驱动不了的改路由,
   本身就是一股味道**——缝变了。

## 三、逐行等价,和两只金丝雀

对每一行改动明确地问:**旧代码在输入是 null / 空 / 默认值时做什么?新代码做什么?往返之后可观察地
一致吗?**

> **出事经过**:一次提交把剩下的列改走一个新面,**删掉了五个 `if (x.Y != null) row.Y = x.Y` 守卫**,
> 换成无条件赋值。新接口文档写着"null 会清空底层的列",于是一个 group 列为 null 的对象现在会**主动
> 清空刚加进去的那一行**,而旧代码保留的是那一行的默认值。同一个提交还在十几个 raw setter 上引入了
> 空字符串回退,**把"null 数据库语义"换成了"空字符串语义"**,往返结果可能不同。两者在提交标题这一层
> 都是静默的,**只有对着之前的 setter 读 diff 才看得见。**

**两只金丝雀**:专门去找 diff 里**被删掉的 null 检查**和**新加的 `?? default`**。
读新契约的 null 和空语义(经常是"null 清空该列"),对着那一列之前的语义(经常是"null 就跳过赋值")比。

## 四、对着已知良好的分支 diff 你的修复

在一条工作分支上修回归时,**trunk 是原始行为的权威来源**。不是记忆,不是读了一半,不是从假设重建。

> **出事经过两次。** 一次按来源的修复,用一个查询加一个虚拟来源集合拼出结果名清单;trunk 实际的机制
> 是一个合计属性加上另一个 helper 推导的值。**清单不一样。** 新路径从没和 trunk 的比过,所以这个修复
> **既没复现原行为也没被验证过,它只是看起来合理。**
>
> 另一次,"全部停止"的回归里,trunk 的取消路径被正确追踪、甚至写进了计划——*先置状态,再移除*——
> 然后那个**移除被刻意省略**了,理由是"最小化、避开出队竞态"。这引入了一个**新的**行为变更:
> 取消的项目随着队列排空**一个一个消失**,而 trunk 是**一次全消失**。单测只断言了症状,所以什么都没抓到;
> **是用户看着应用抓到的。追踪差异不等于匹配差异。**

**怎么用**:

1. 从 trunk 里**端到端**读出那条 legacy 路径,包括它调用的 helper。**不要停在第一个看起来对的方法**:
   追出到底是哪个清单或哪个值在驱动输出。
2. 写完修复之后,**逐行 diff 你的路径和 trunk 的**,明确回答两个问题:报告的问题真的修好了吗?
   **你有没有引入任何新的行为变更**——不同的清单、顺序、守卫、默认值或取值?
3. 迁移把两个 legacy 清单塌成一个时,**挑那个驱动正确性的,并说明为什么**。
4. **复现 trunk 的路径,不要以"最小"或"更干净"为由丢掉它的任何一行**——一次移除调用、一次状态设置、
   一条消息、一个事件——除非你能证明那一行是死的。**"最小"永远压不过"不引入新行为变更"。**
5. **在可观察层面验证,不只是症状层面。** 断言"这个 bug 没了"的单测通过,**不证明对齐**。

## 五、合并取守卫的并集

把同一个读取/解析/写入的几份独立实现塌成一份共享契约时,合并后的版本必须携带**所有副本防御的并集**,
而不是你最近读的那一份的形状。

> **出事经过**:四个地方解析同一个存储的选择。计算路径那个 helper 末尾有一个 coalesce 到默认值;
> 一个 view model 没有。合并成一个"非空 reader"并 catch 掉解析异常之后,**那个 coalesce 被丢掉了**。
> 反序列化器对字面量 `null` **返回 null 且不抛异常**(而格式错误会抛),于是那个非空方法可以把 null
> 返回给两个非空调用方,其中一个在计算路径上。**被删掉的那个守卫是唯一覆盖过那种输入的东西。**

**为什么能泛化**:**互相分歧的副本不是待归一化的噪音。** 每一个守卫都是某个撞上了它所防御的那种输入的人
加的,所以**一个守卫在一份副本里有、另一份里没有,这是证据,不是不一致。**

## 六、见证者待在契约外面

一次合并把散落的解析/读取逻辑拉进一份共享契约时,**测试的见证者必须待在它外面**——自己查、自己解析——
即使这会在代码树里留下一份**刻意的重复**。

> **出事经过**:合并一次"读存储值"的时候,oracle 也被指向了新的共享 reader。于是那道门断言的是
> "API 的答案等于 oracle 的答案":**同一个函数的两次调用。** 共享 reader 内部有 bug 的话,
> 两边会一致,门会绿。修法是让 oracle **自己裸解析存储的文本**。

**一个 oracle 唯一的价值是它能不同意。** 独立性必须对**被测的那一步**成立,不只是文件层面:
"oracle 没有调用那个命令"是不够的,**当被见证的东西就是两边现在共用的那个解析时**。
共享的**查找**藏起一个键匹配缺陷,和共享的**解析**藏起一个格式缺陷,是一样的。

## 七、值相等不等于身份相等

每一次表示变更的物化点,**枚举下游的比较点**——相等运算符、`Equals`、switch、字典键、引用身份——
**在没改过的代码里**,并逐个证明它仍然会触发。**追到值死掉为止,不只追到直接消费方。**

> **出事经过**:一个颜色类型的相等比较的是"已知颜色名 + 状态",所以**一个从数值构造的颜色永远不等于
> 那个命名的透明色**,即使分量完全相同。一次导出的"跳过空白"门——**一行没改过的 legacy 代码**——死了,
> **46 个不可见的覆盖层发了出去。那个场景有一个通过的值层测试**,因为它是通过数值转换断言的。
> 评审验证了**哪些值**流过去,但**在类型边界上停止了追踪**;那个比较点在没改过的代码里、
> 在一个一行 diff 的项目里、往下两跳——**而按 diff 体量分配注意力的做法永远不会打开没改过的消费方。**

**最便宜的兜底**:在两个构建上产出同一个产物,**直接 diff 产物**——条目数、大小。
**测试团队就是靠比两个文件大小发现这个 bug 的。**

## 八、一列两种语义

两个读取方对同一个存储列不一致时,**不要假定其中一个是 bug 然后去统一它们**。先查**从那一列派生出来的
每一个属性**:一行 legacy 数据经常在一个字段上跑**两种有意为之**的语义。

**怎么用**:改一个 getter 之前,**grep 那一列的原始字段名**,不只是你要改的那个访问器。
如果第二个属性读的是原始值而你的读的是解析后的,**那个差异是一份契约。留着它**,要紧就在调用方过滤。

## 九、重新定型:枚举每一个来源

一次重构把一个富对象(数据库行、实体句柄、聚合包装)换成"快照 + 注入的服务"时,
**在选定新参数列表之前,枚举旧对象当初是对着哪些不同的来源解析的**。

> **出事经过**:旧构造函数收一个行句柄。**一个成员是对着那一行自己的存储解析的,另一个是对着宿主工程的
> 服务解析的。** 两个被塌到同一个服务参数上:四个调用点里三个是对的,**第四个静默地错了**——
> 那里一次优化从自己的库读结果,却对着打开它的那个工程解析布局。

**重新定型看起来是彻底的,因为类型变了而且全都编译过。丢掉的东西是不可见的:不是某个成员,
而是某个成员当初是对着哪个对象解析的。**

**怎么用**:对旧对象暴露的每个成员问"**这个到底是从哪个对象读的**"。把答案分组。**多于一组就意味着
多于一个参数。**

## 十、死代码要可达性地图

删掉一个被取代的实现之前,**画出还有什么能到达它**,不只是什么引用了它。引用扫描说"这些文件提到了那个
runner";**可达性地图说"而且这个守卫把大部分生产流量送回给了它"。**

> **出事经过**:一次迁移里新路径的门是"候选项是某种形状"。另一种形状是那个类型的**兄弟**,不是子类型,
> 于是每个持有它的用例**仍然端到端走 legacy runner**。四个类的对齐门全绿、门也说 true;
> **活并没有做完,而那时删掉 runner 会弄坏那些用例。**

**怎么用**:对新路径上每个回退或守卫,问**多大比例的真实输入会走它**,并且**查类型层级而不是类型名**
——**兄弟读起来像子类型**。用**拓宽新路径**来关掉缺口,而不是绕着它删。

## 十一、零引用门要 grep 每一种访问写法

宣布某个区域或分支"不再有某个退役类型"时,**grep 每一种能到达它的写法**,不只是类型名。
**先枚举那个退役类型的访问器**(grep 它的扩展方法文件里的扩展声明、以及返回它的方法),
用那份清单拼出模式,再跑门,**然后把加宽后的模式在已经宣布干净的区域上重跑一遍**。

> **出事经过三次。** 类型名 grep 报告某区域**干净**,而两个活的集合访问器调用点还在——
> **扩展方法和集合访问器返回那个退役类型却从不提它的名字。**
> 判断一个命名空间导入还需不需要时,枚举了那个命名空间的 **175 个类型**、一个都没在文件里找到、
> 把导入删了、**构建挂了**:那个文件用的是一个**扩展方法**,它既不提自己的声明类型也不提自己的命名空间。
> 最尴尬的一次:描述和退出门声称"这个上下文之外没有文件再引用引擎了"。**有两个**,都是组合根代码。
> 扫描匹配了引擎的**子**命名空间,漏了**根命名空间**写法加一个裸导入。
> **一个包的根命名空间也是一种访问写法。**

**一道报告"干净"但其实不干净的门,比没有门更糟,因为它终结了搜索。**

**报增量,不要报绝对值。** "51 个文件降到 2 个,都是组合根"是诚实的;**一个绝对的"零",
离变成假陈述只差漏掉一种写法。**

## 十二、消除,不要重新分配

目标是"消除某一层对另一层的引用"时,**不要靠把它们挪到第三层、再把那一层的传递作用域拉宽来解决**。
**度量是整个代码库里引用的总数**,不是哪个程序集持有它们。

> **出事经过**:一行导入换来了十二行新的——一个 UI 文件、十一个测试夹具,外加测试项目上一个传递共享的
> 项目引用。用户立刻打回:*"don't you think that's even worse? more projects refer Persistence."*

**怎么用**:任何"挪调用点"的重构之前,**数两边被触及的引用数**。如果这次移动让导入散布到比它移除的
更多的文件或项目里,**那是管道,不是进展**。消除类工作要优先选**删除**导入的级联,而不是**改道**导入的。

## 十三、一个用例一条路径;缝会退役

1. **一个用例一条抽取路径。** 一个已有用例的消费方走**那一条**共享的、对齐验证过的路径。
   **绝不为某个消费方另造一条读取路径**,即使它看起来更原生或更便宜。
2. **因排期而生的缝,从出生就带着退役触发条件**,而**落地共享路径的那次改动就把它们退役掉**。
   把退役写进那个任务的计划里,不要写进一条没人再读的注释。
3. **一对症状——同一个机制产生的一个假阳和一个假阴——证明的是设计 bug,不是接线 bug。**
   当修好一个方向会弄坏另一个方向时,**停止打补丁,把那个机制拿掉。**
4. **绝不改变 legacy 决策过程的形状。** 一个 legacy 先按切片决、再按点决;那个缝把它塌成了一次按点比较。
   **常见用例上输出相似,边界行为不同。**
5. **往迁移过来的机器上加补偿之前,先问这台机器该不该存在。** 反复给一个缝加成员的修复轮次,
   **就是"这个缝本身才是缺陷"的味道。**

## 十四、按用例切,不按符号切

每次迁移改动都是**一个用例端到端**:持久化支持 → 应用服务方法及其契约 → 所有消费方迁移 → 测试。
**符号的退役是"所有消费方都迁走了"的结果,绝不是目标。**

标题描述用例("把删除改走应用服务"),**绝不描述符号**("去掉那个仓储属性")。
一个会话如果忍不住要围绕"让 X 消失"来组织,**停下来,围绕碰到 X 的那些用例重新表述。**

**这条禁止的东西**:围绕符号/字段/可见性起标题的改动;碰多个不相关用例的改动;不是端到端做完一个用例的
"清理"改动;形如 "A: 删字段, B: 删属性, C: 删类" 的任务结构;**在发现缺口时增量地设计公共面**——
一个用例的面在它那次改动**开始时就锁定**。

## 十五、确认一个用例入口真有调用方

把一个目录条目提升成新公共接口上的一个方法之前,**在当前代码库里 grep 那个符号。零调用方 = 不是真的。**

> **出事经过**:一份目录列了一项能力,带着执行者、触发条件、流程和一个具名的当前服务,提议的接口也包含了
> 对应的方法。**grep 在整个解决方案里零命中**,而那个具名服务只有一个生产调用方,在计算引擎内部。
> **那份目录发明了它。**

**发明出来的能力,正是抽取所禁止的那种行为变更。**

## 十六、对着起始分支重新推导范围

一个提前于它的前置项排期的工作项,**在前置项落地的那一刻就过期了**——而且它落在**特性分支**上,不是 trunk,
所以**基于 trunk 的 grep 会一直确认那些过期的说法。**

> **出事经过**:某个工作项"今天"那一段的五条说法里,三周后有三条是假的。七个任务里有两个描述的是前置项
> 已经交付的活:被标成**本项目最大的任务**的那个已经完成约 90%。**对 trunk 的 grep 显示那个退役类型
> 817 处命中、232 个文件,愉快地确认了每一句过期的话;而工作项真正起始的那个分支上是 39 处、5 个文件。**

**怎么用**:把每句"今天 X 还在做 Y"变成**那个分支上的一个符号计数**。
**注意 pathspec**:`git grep` 带一个不存在的路径前缀会静默返回空,**那个零读起来正好像"已经迁完了"**。
**用一个你确定存在于同一路径下的符号去证明那个零。**

## 十七、接口隔离必须真的隔离

把一个接口拆成角色形状的窄接口(身份、读、写、生命周期)时,**验证每个窄接口真的省掉了它声称省掉的成员。**

> **出事经过**:一个四接口家族被引入并被表扬。一条竞争的评审正确地指出:读接口刻意省掉了每一个标量 getter,
> **而所有 getter 都住在 settings 接口上,那个接口同时暴露 setter。** 于是任何想**读**一列的消费方
> 都必须依赖写入方的面。**这个家族没有交付任何真正的只读缝。**
